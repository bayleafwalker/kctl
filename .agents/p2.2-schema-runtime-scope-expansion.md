# P2.2 schema-runtime packaging scope expansion

The P2.2 kctl consumer migration is coordinator-owned because it changes the
stateful central-schema boundary and the distribution contract together. The
repository's standing dispatch scope permits `kctl/`, `tests/`, `docs/`,
`verification/`, and `.agents/`, but it does not include root packaging files.

For this bounded migration, the coordinator authorizes these additional paths:

- `pyproject.toml`, to bump kctl to 0.1.3 and add the immutable GitHub wheel pin
  for `vuoro-schema-runtime` 0.1.0;
- `uv.lock`, to lock that exact URL and SHA-256 digest.

This is an explicit one-item scope expansion. `kctl.dispatch.json` remains
unchanged: its reusable default must not be weakened to make a packaging-aware
exception look routine. The release validator and tests remain inside their
already permitted `verification/` and `tests/` roots.

The shared dependency is limited to pure `MigrationAsset`, contiguous-version,
identifier quoting, schema SQL rendering, and UTF-8 SHA-256 plumbing. Kctl
retains its PostgreSQL runner, transaction and advisory lock, ledger I/O,
compatibility output and reason strings, relation-shape checks, role/grant
policy, and environment binding authority.
